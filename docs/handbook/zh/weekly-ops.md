## 你现在在哪,这章解决什么

广告开了,店正式营业。但游戏攻略最怕过期:兑换码过期了没人管、Boss 改版了攻略还教旧打法——玩家来一次发现是废纸,就不来第二次,Google 也会把排名让给别人。

这一课给你一套固定节奏:每周一 30 分钟,每月 10 分钟,每季度 5 分钟。**固定节奏是网站永不过期的唯一秘诀。**

## 这章做完你会得到

- 一套照做就行的每周动作清单(可复制进日历)
- 每月、每季度的固定动作

## 每周一,30 分钟

### 动作一:跑保鲜检查,把报告变成待办(15 分钟)

**做什么**:让网站自己告诉你哪些页过期了。
**怎么做**:终端输入:

```bash
pnpm refresh-audit
```

**你会看到**:一张清单。两种级别——**P0 最紧急:兑换码页超过 7 天没更新(拖过 30 天问题升级);P1 次紧急:Boss 攻略和排行榜这两类页面超过 90 天没更新**(只有这两类会产生 P1,因为它们过时会误导玩家;其他页面不会)。然后把清单粘贴给 AI 助手,让它整理成待办:

```text
下面是我的 pnpm refresh-audit 报告:
<粘贴报告>
把 P0/P1 转成可执行清单:
1. 需要我提供新数据的页面 → 逐页列出具体要什么(最新码列表/新版本机制改动)
2. 我确认内容仍准确、只需刷新的页面 → 把 lastModified 更新为今天
3. gameVersion 落后的页面单独列出
不许自行修改任何内容事实。以复选框清单输出。
```

> 注意:仓库里那个「每周自动检查并开 issue」的功能,**默认只在 AnvilWiki 官方仓库生效,你的站收不到自动提醒**——所以要自己每周跑这一条。想让 GitHub 自动开 issue 提醒也可以:删掉 `.github/workflows/content-pipeline.yml` 里 `if: github.repository ==` 那一行条件(让 AI 助手帮你删,一句话的事)。

### 动作二:更新兑换码(10 分钟)

去官方推特/Discord 收集新码和确认过期的旧码,然后:

支持技能的 AI 助手直接说(斜杠命令):

```text
/anvil-update-codes 新码:<code列表>;已确认过期:<code列表>
```

普通提示词版:

```text
更新 src/content/wiki/en/codes/ 下的 codes 文章:新码追加到 frontmatter active 最前;
过期码 status 改 expired(保留不删除);lastModified 改今天;title/summary 中码数量与年月同步;
若存在其他语言版,同步数据(code 字段不译,reward 等文案译)。
写完运行 pnpm check-content && pnpm build,全绿才算完成。
```

**确认做对了**:兑换码页出现新码,过期码搬进「已过期」表格(不删——还有人搜「旧码还能用吗」,留着接长尾流量)。

### 动作三:看数据定下周选题(5 分钟)

`git push`(Cloudflare 自动重新上架)→ 打开 GSC「效果」页看这两天哪些词带来点击 → 挑 1 到 2 个上涨的词,下周用产页那一课套路写对应新页。

看数据别凭感觉,对着四条及格线看(数据来源:GSC「效果」;浏览深度用 Cloudflare Web Analytics 或 GA4):

| 指标 | 及格线 / 目标 | 不及格怎么办 |
|---|---|---|
| CTR(点击率) | ≥ 2% | 检查标题(title)、描述(description)、H1 三件套和标题吸引力——含不含「游戏名 + 关键词」,有没有让人想点的钩子 |
| 每日点击 | 1000 次/天是目标 | 新站从个位数涨起正常;看趋势,连续一周不动才要动作(补页面/换词) |
| 人均浏览页数 | ≥ 1.5 页 | 低于 1.5 = 内链不够:每篇补 1 到 2 条指向相关文章的内链 |
| 每周新增内页 | 10+ 篇 | **只加不改旧页**——新增页面是给 Google 的增量信号 |

**复盘纪律:只认面板上的数。**

- **结论要有出处**:「这周涨了」必须能指到 GSC 或统计面板的某个数字;指不出数字的结论,下次复盘不作为依据。
- **动作不是成果**:「发了 10 篇」「换了主题色」是你做的事,不是网站的成果——成果只认 CTR、点击、收录这些面板数变了没有。
- **旧结论被推翻,当场改口**:上周记的「这个词没量」这周被数据打脸,就在原笔记上改掉,别留一句过时的「现在时」误导下周的自己。

### 可选装备:Clarity 免费热力图(装一次,每周看 5 分钟)

数字告诉你"有多少人来了",**Clarity 告诉你"他们在页面上干了什么"**——免费的点击热力图 + 用户操作录屏,每周看两件事:用户**卡在哪**、**广告位有没有被点**。

1. 打开 [clarity.microsoft.com](https://clarity.microsoft.com) → 微软账号登录(免费)→ **Add project** 填你的域名
2. 安装方式选 **Manual install**,拿到一段 `<script>` 跟踪代码
3. 打开 `src/components/layout/BaseLayout.astro`,把代码粘到 `</head>` 结束标签之前 → push 重新部署
4. 回后台等几分钟,状态变 Receiving data 就通了

完整步骤(含配过 CSP 要放行哪些域名)在仓库文档 [`docs/deployment.md`](https://github.com/PNGTRID/AnvilWiki/blob/main/docs/deployment.md) 的「用 Microsoft Clarity 看用户在你站点上干什么」一节。脚本异步加载,不影响 Lighthouse 分数。

## 每月一次(各 10 分钟)

```bash
# 1. 有多语言站才跑:看翻译缺了多少
pnpm check-i18n

# 2. 把模板作者的更新搬进来(第一次用,三行都要跑)
git remote add upstream https://github.com/PNGTRID/AnvilWiki.git
git fetch upstream
git merge upstream/main
```

第二组命令的意思:把官方仓库(叫 upstream)设为关注对象,拉取它的最新版,合并进你的站。**如果终端出现 CONFLICT 字样别慌**:把冲突文件名告诉 AI 助手,说「配置和内容保留我的,代码听官方的」,让它逐个解决——这一步本来就适合让 AI 做。详细讲法在开发手册「同步」章。

再花 10 分钟看 AdSense 报表:哪类页面 RPM 最高(通常是排行榜和兑换码)→ 下月多写哪类。

## 每季度:SEO 体检(把这段发给 AI 助手)

```text
对本站做 SEO 体检,只读不改:
1. SITE_URL(wrangler.toml [vars] 或 .env)含 https:// 且为正式域名
2. 全部文章 title≤80、description 40–165、summary 为直答(列违规清单)
3. og:image/twitter:image 为绝对路径
4. noindex 是否误用
5. 运行 pnpm check-sitemap;build 后运行 pnpm check-links,报告非 200/死链
6. 多语言 hreflang 覆盖是否完整
输出问题表:文件/问题/建议修法,经我确认后再改。
```

## 长期心态

- 第一个站跑通后,第二个站边际成本极低——选品、建站、产页、部署、运营,这本手册你已经完整走了一遍。
- 忘了每周跑检查?在手机日历建一个每周一重复的提醒,标题写「30 分钟保鲜」。

## 卡住了怎么办

- **「refresh-audit 报告看不懂」**:不用懂,整段复制粘贴给 AI,提示词会把它变成待办清单。
- **「月度 merge 冲突」**:把冲突文件给 AI,口诀「配置和内容保留我的,代码听官方的」。
- **「忘了跑」**:日历每周一循环提醒,比意志力可靠。

## ✅ 验收(全部成立才算完成)

- 本周跑过一次 `pnpm refresh-audit`,P0 清零(兑换码页 7 天内更新过)
- ☐ 连续三周,同一时间做了这三件事
- ☐ 看得懂 GSC「效果」页:哪几个词带来了点击

## 学完之后

放大,从复制站那一课开始:**[把第一个站打磨成模板](/zh/landing/docs/templatize-your-site)**,30 分钟复制出下一个游戏站。想先深度定制这个站,进[开发手册](/zh/landing/docs/architecture)(加栏目、加语言、换皮肤、开评论统计);做出成绩后,把你的站提 PR 加进 AnvilWiki 官网展示墙(改 `src/config/landing.ts` 里的 showcase 数据)——你的真实案例,就是这套模板最好的广告。
