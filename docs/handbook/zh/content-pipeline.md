## 你现在在哪,这章解决什么

学习手册的产页流水线是「一篇一篇聊」;批量铺页那课是「本地批量生成」。这一课是第三种形态:**关键词清单直接变成仓库里的草稿 PR**——生成在云端、门禁在云端、你在本地填肉,适合手机上想推进度的时刻,以及「攒了一批词想一次性铺出去」的场景。

## 设计原则:CI 里没有 AI

管道里的每一步都是**确定性脚本**:CSV 解析、脚手架生成(bulk-new-posts)、八道质量门禁。没有任何 AI key 进 CI——AI 创造力发生在你的本地会话,云端只负责「骨架合法+门禁全绿」。这决定了它的分工:**管道铺骨架,你(和本地 AI)填血肉**。

## 跑一次的完整流程

1. **一次性设置**:仓库 Settings → Actions → General → 勾选 **Allow GitHub Actions to create and approve pull requests**(不勾,管道到最后一步开不了 PR)
2. **准备 CSV**:一行一个词,格式见仓库 [docs/content-pipeline.md](https://github.com/PNGTRID/AnvilWiki/blob/main/docs/content-pipeline.md)(关键词/页面类型;词的挑选按学习手册选词那课的三条判断)
3. **跑管道**:仓库 **Actions** → **Auto content PR** → **Run workflow** → 粘入 CSV → 运行
4. **管道自动**:bulk-new-posts 生成全部草稿 → 八道门禁逐条过 → **只有全绿才开 draft PR**(任何一条红,管道响亮失败,不开 PR)
5. **填肉**:本地拉分支,在 AI 会话里逐篇填真实游戏数据(素材纪律、draft 纪律全部适用)→ 逐篇验收
6. **人审 merge**:确认后合并——**AI 和管道都碰不到 main,合并权在你**

## 和其他两条产线的分工

| 产线 | 场景 | 节奏 |
|---|---|---|
| 产页流水线(学习手册) | 日常一篇一篇 | 质量最高,人工最重 |
| 批量铺页(学习手册) | 本地一批 10-20 篇 | 本地生成、本地验收 |
| **内容管道(本课)** | 云端批量铺骨架 | 门禁前置,人审兜底 |

三条产线守同一条纪律:**批量生成可以,分批上线**——首版节奏那课的结论不过时。

## 三个经典错误(提前替你踩)

- **没勾 Actions 开 PR 权限就跑管道**:白跑,最后一步开不出 PR——先做一次性设置。
- **把管道当「全自动印钞机」**:骨架自动,血肉必须本地填+人审;直接 merge 空壳草稿=批量生产废页。
- **CSV 里塞没验证过的词**:词的判断(意图/竞争/能不能做出更好的页)在选词那课,管道不替你选词。

## 本课新词(就 3 个)

- **确定性生成器**:同样输入必得同样输出的脚本——管道可信的原因(没有随机性就没有惊吓)。
- **门禁前置**:质量检查在开 PR 之前全跑完,红一条连 PR 都不会有。
- **draft PR**:草稿拉取请求——看得见、评得了,但不能 merge,适合「骨架就位、血肉未填」的中间态。

## ✅ 验收(全部成立才算完成)

- ☐ 管道跑完开出 draft PR(或明确知道哪道门禁拦了)
- ☐ 草稿在本地逐篇填了真实数据、过了验收
- ☐ merge 是你亲手点的
