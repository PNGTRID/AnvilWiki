## 你现在在哪,这章解决什么

用模板的过程中你修了 bug、加了好东西——烂在自己仓库里可惜。这一课是把它交回官方的完整路径,以及另一种贡献:**把你的站本身展示出去**。

## 贡献五步

1. **先开 issue 讨论**:到仓库 Issues 描述场景和想法——大改动先看官方 PRD 有没有相关决策,避免白做;小修(错字/死链/小 bug)可以直接 PR。
2. **分支开发**:守架构章的楼层规矩——文字进 JSON、颜色用 CSS 变量、零 JS 框架、代码层不出现游戏专属字符串。
3. **自验**:`pnpm lint && pnpm typecheck && pnpm test && pnpm build` 全绿(上一课的验证清单)。
4. **提 PR**:描述里贴验证输出;等 CI 绿、等作者审——CI 红了按自证课的方法看日志定位。
5. **配套交付**:加了纯函数(放 `src/lib/` 的)配测试;加了组件补文档——没测试的纯函数和没文档的组件,审起来都慢。

## 你的站本身也是贡献

把站提上官网展示墙:PR 修改 `src/config/landing.ts` 里的 showcase 数据(站点名、链接、一句话介绍)。**真实的成功站,是这套模板最有说服力的广告**——反过来,展示墙也是新手的选品与设计参考(建站前逛一遍别人怎么做)。

## 卡住了怎么办

- **「PR 被 CI 拦了」**:点开红 job 看日志最后一行,本地跑同一条命令复现修掉,推上去 CI 自动重跑。
- **「不知道我的改法符不符合官方方向」**:这就是第 1 步先开 issue 的意义——花五分钟问,省五天白做。

## ✅ 验收(全部成立才算完成)

- ☐ PR 描述里贴了完整的自验输出
- ☐ 新增纯函数有测试,新增组件有文档
- ☐ (可选)你的站已提交展示墙 PR
