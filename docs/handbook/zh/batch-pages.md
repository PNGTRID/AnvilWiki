## 你现在在哪,这章解决什么

产页那一课你学会了一天写 10 篇——但那套流程是「一篇一篇聊、一篇一篇写」,产能天花板很快到。而搜索流量的大头从来不是首页:首页只对准站名一个词,几十上百个**内页**各对准一个搜索词,合起来才是流量主力。

一个只优化首页的站,等于只开了店门没摆货架。这一课把「写一篇」变成「做一批」:从一份关键词清单出发,批量铺出对准不同搜索词的内页。

## 这章做完你会得到

- 一份从真实搜索词里挖出来的内页清单(`new-posts.csv`)
- 几十个对准不同搜索词的草稿页——批量脚手架、批量生成、批量验收
- 一条可反复跑的产页流水线:清单 → 脚手架 → 统一提示词 → 验收

## 先认识几个词

- **内页**:除首页外的每个内容页(一篇攻略、一张兑换码表、一个排行榜)。每个内页 = 一个流量入口,各自对准一个搜索词。
- **统一提示词模板**:一份固定的「内页生成提示词」——骨架、规则、验收全部写死,只有素材逐篇换。批量最大的敌人是每篇临时想结构:质量不稳定,句式还容易重复。
- **灌水**(doorway pages):为了搜索批量造一堆空洞页面的行为。Google 明确打击——批量是产能工具,不是灌水许可证,本课最后单独讲怎么避开。

## 第 1 步:列内页清单(词从哪里来)

不要拍脑袋。四个来源,按可信度排序:

1. **GSC「效果」页**(收录那一课开过):哪些词带来了展示却没被点走——现成的机会清单。
2. **竞品 wiki 的页面结构**:搜同类游戏的 wiki(如 fandom 站),看它有哪些页面——玩家需要什么,它已经替你验证过了。
3. **Google 自动补全和相关搜索**:输入游戏名,看下拉和页尾推荐。
4. **游戏官方更新日志**:新 Boss、新活动、新版本=新搜索词,抢首发。

每行一个词,顺手标注意图(兑换码/boss/教程/排行榜——产页那一课的意图分类表)。意图不明的单独列出来问清楚,不要猜。

## 第 2 步:写一份统一「内页生成提示词」

先把清单变成脚手架文件 `new-posts.csv`(放仓库根目录,列:`locale,category,slug,title,description`,description 可后补):

```bash
pnpm bulk-new-posts --dry-run   # 先看计划:哪些会建、哪些因已存在被跳过
pnpm bulk-new-posts             # 真实写入。全部是 draft:true 草稿,不会进 build
```

然后**同一份提示词**喂给 AI 批量填充(支持技能的助手直接说「按这份关键词清单批量写文章」,触发 anvil-batch-articles 技能;下面是通用版):

```text
下面是我的内页清单(每行:关键词,意图分类):
<粘贴清单>
为每个关键词生成一篇文章页,统一骨架,禁止模板句复用:
1. 首个 H2 = 关键词的问题式改写,其后紧跟 40-60 词直答段;正文不写 H1
2. 数据进 Markdown 表格,步骤用有序列表
3. frontmatter:description 40-165 字符;summary 写 40-60 词直答;tags 复用站内已有标签
4. 每篇至少 1 条内链,只指向确实存在的页面(不确定存在就不加)
5. 素材不足的关键词:该篇保持 draft:true 并在正文标注「待补充」,禁止编造兑换码/Boss 数值/掉落率
6. 同一批文章:开头句式、小节命名、表格列头不得雷同,每篇从关键词本身的问法出发
完成后运行 pnpm check-content && pnpm build,全绿才算完成;失败项列清单修复后再跑。
```

## 第 3 步:批量验收,逐篇翻正

- `pnpm check-content && pnpm build` 全绿后,把仍是 draft 的篇目列成清单。
- 素材真实的篇目,逐篇(或逐小批)确认后把 `draft: true` 改掉、删掉「待补充」标注,重新 build 上线。
- 抽查 3 篇:每篇是否独立回答了一个真实搜索问题?句式有没有雷同?内链是否全部可达?

**翻正也要讲节奏**:一次生成 40 到 60 篇草稿没问题,但**别一次全放出去**——首版只翻正 10 到 15 篇核心页(codes / tier list / guide 高价值词)先上线,之后每周翻正 10+ 篇。实测:第一版页面太多,质量被稀释,反而拖累整站排名(产页那一课末尾讲过同一结论)。

## 最大的坑:批量不等于灌水

这一节是本课的核心,值得反复读:

- **每篇必须独立有用**。判断标准:删掉其他所有文章,这一篇单独看还是一篇能解决玩家问题的攻略。做不到的,宁可不做。
- **禁止编造数据**。兑换码、Boss 血量、掉落率——没有用户提供的数据源就写不出来,标「待补充」等素材。一条假兑换码毁掉的是整站信任,Google 和玩家都不会给第二次机会。
- **同批不许模板句复用**。同一模板换名词批量生成,是 Google 判定 doorway pages 的经典特征。
- **内链只指真实页面**。批量生成的内链最容易指向不存在的路径,build 后跑 `pnpm check-links` 是硬门禁。

## 卡住了怎么办

- **「bulk-new-posts 报 category 不合法」**:你的清单里有 navigation.ts 不存在的分类。先按「三处一致」把分类加进去(开发手册有专门一章),再重跑。
- **「建出来的页面在哪看?」**:`pnpm dev` 启动后按输出的 URL 逐篇看;draft 页面只在 dev 可见。
- **「build 挂了」**:先跑 `pnpm check-content` 看 lint 清单;批量问题通常是同一类错误(如 description 太短),一次修一类。

## ✅ 验收(全部成立才算完成)

- ☐ `new-posts.csv` 通过 `--dry-run`,建了多少、跳了多少说得清
- ☐ 批量生成的全部页面 `pnpm check-content && pnpm build` 全绿
- ☐ 抽查 3 篇:独立有用、句式不重复、内链全部可达

## 学完之后

批量铺完内页,学习手册还差最后一块拼图:收录只是入场券,排名和 AI 引用才是流量——[去 SEO 进阶](/zh/landing/docs/seo-traffic),把每个内页对准的搜索词真正做满。之后:回每周保鲜那一课把周节奏跑稳;进[开发手册](/zh/landing/docs/architecture)深度定制;或把你的站提 PR 加进 AnvilWiki 官网展示墙(改 `src/config/landing.ts` 的 showcase 数据)——你的真实案例,就是这套模板最好的广告。
