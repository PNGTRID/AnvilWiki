## 先看一个真实场景

到现在为止,「多少人来了、看了什么」Cloudflare 和 Clarity 已经答了。什么时候需要 GA4:你开始问「从兑换码页进来的人,有多少接着看了攻略?」「回访玩家和搜索进来的,行为差在哪?」——**行为路径和转化问题**,才是 GA4 的主场。没到这一步,装了也是吃灰;到了这一步,10 分钟装完。

### 第 1 步:建账号和媒体资源(5 分钟)

打开 [analytics.google.com](https://analytics.google.com) → 登录 Google 账号 → **开始衡量**,建账号和媒体资源(名称随意,时区选你所在时区)。

### 第 2 步:添加网站数据流,拿衡量 ID

媒体资源里 → **数据流** → **添加数据流** → 选 **网站** → 网址填 `https://你的域名` → 创建。记下**衡量 ID**(样子像 `G-AB12CD34EF`)。

### 第 3 步:填进环境变量,重新部署

把衡量 ID 填进环境变量 **`PUBLIC_GA_ID`**(Cloudflare 项目 Variables,或本地 `wrangler.toml` 的 `[vars]`)→ 保存并重新部署。

### 第 4 步:自己验证一次

打开你的网站,**点一次同意横幅的「同意」**→ 回 GA4 → **报告** → **实时**,应看到 1 个活跃用户(就是你自己)。

**⚠️ 装完没数据的两个最常见原因**:

- **GA 在模板里是同意横幅门控的**:访客不点「同意」,GA 脚本就不加载——这是模板保 Lighthouse 满分和隐私合规的设计,不是 bug。所以验证必须自己点一次同意。
- **报表有延迟**:实时报告即时,常规报告最多延迟 24-48 小时,别急着判「坏了」。

## 三个经典错误(提前替你踩)

- **新手期就装**:问题还没到,装了只看一个总访问量——Cloudflare 免费给你的就是它。等「路径」问题出现再上,课也在等你。
- **以为没数据是坏了**:先检查是不是没点同意横幅,再等 48 小时;两个都不是才来找 bug。
- **只用 GA4 不看 GSC**:GA4 看站内行为,GSC 看搜索表现——两边对照才完整,别偏科。

## 本课新词(就 3 个)

- **衡量 ID**:GA4 给你数据流的 `G-` 开头编号,模板靠它加载 GA。
- **同意横幅**:访客对 cookie 的授权开关,模板内置——GA 由它门控是隐私合规设计。
- **转化路径**:玩家从进站到目标动作(复制码/看完攻略)走过的路线,GA4 的核心价值。

## ✅ 验收(全部成立才算完成)

- ☐ 实时报告里看到自己(点过同意之后)
- ☐ 你知道常规报告有 24-48 小时延迟
- ☐ 你说得出 GA4 和 Cloudflare/Clarity 的分工:行为路径 vs 人次数 vs 页面行为
