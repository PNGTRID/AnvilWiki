# AnvilWiki 挖词选品（自动找词）

给「下一个站做哪个游戏」这个问题供弹药：多渠道挖候选 → 逐个快验 → 判决打分 → 落盘决策管理表。**只读研究技能**——不改任何代码与内容文件，只写 `seo-reports/` 下的报告（该目录已 gitignore）。

方法论来源（先读再动手，本文件是它们的可执行版）：

1. `docs/sourcing.md` — 9 个挖词渠道 + 意图满足度 + 判决框架（打分表 / KD 分档 / 早期爆发轨 / 两判据 / 复查节奏）
2. `docs/game-selection.md` — 四层漏斗（候选定级后的终审，在本技能之外）
3. `docs/handbook/zh/find-candidates.md` — 「每天 20 分钟填候选池」的人工节奏（本技能是它的自动化版）

## 红线（违反即报告作废）

1. **禁止编造数据**。搜索量 / KD / 在线人数 / 播放量，任何查不到的数字一律标「未测」并写明原因——不许估算，不许拿印象充当数据，不许把旧数据当本周数据。
2. **未测 ≠ 零**。缺证据的项不计 0 分，最终建议必须点名哪些项是未测。「没测出机会」和「测出了没机会」是两句话。
3. **平台内流量 ≠ 独立需求**。聚合站推荐位、TikTok 播放量只证明平台愿意推；只有平台内信号的候选留在观察，除非 SERP / 搜索萌芽佐证。
4. **分数是参考，拍板在用户**。给出建议判级 + 证据链，不替用户把「做」写死；表格里【决定】列只写「建议：X」，由用户改定。
5. **不覆盖用户结论**。决策管理表里用户已填过「做 / 不做」的行，只追加复查记录，不推翻重写。

## Step 0 — 输入收集（缺什么问什么，一次问完再开工）

- 目标市场（默认英语 / 美国——多数游戏词的最大盘）
- 已有站点与已判过「不做」的词（避免重复挖、避免撞自己的站）
- 有没有付费工具账号（Ahrefs / SEMrush / Similarweb）——有则解锁渠道 8 与搜量 / KD 实测
- 本轮预算（默认：一轮新增 3-5 个候选，宁缺毋滥）

## Step 1 — 多渠道挖候选

渠道编号对齐 `docs/sourcing.md` 的 9 渠道；其中渠道 2（社媒）拆成 A2（Reddit，可抓）与 B1（TikTok / YouTube，登录墙）。优先跑 A 组，抓不到就换通道，不硬试也不空手而归。

**A 组 · agent 自助通道（直接搜索 / 抓取）**

| 渠道 | 怎么执行 |
|---|---|
| 1 · Steam 新游信号 | 🚨 steamdb.info 反爬严格，抓不到别硬试：换 steamcharts.com 抓近期上榜，或搜「trending steam games this week」类二手汇总。判据：玩家曲线**最近几天才出现**的才是真新游——发布日期会骗人（老游戏改名重发） |
| 2a · Reddit 异常值 | 抓 old.reddit.com 的 r/WebGames、r/incremental_games、r/playmygame 等版块：低赞账号的高互动帖、同一小游戏被多个账号自发提起 = 信号（抓不动就退回 `site:reddit.com` 搜索） |
| 3 · CrazyGames 新页 | 抓 `crazygames.com/sitemap.xml` 拉最新游戏页，逐个看玩过人数 / 评分 / 上线时间——两周以内、数据在涨、评分不差，记入候选 |
| 4 · Trends 飙升词 | 抓 Trends RSS：`https://trends.google.com/trending/rss?geo=US`（geo 换目标市场），从飙升词里筛游戏词；RSS 失效就搜「Google trending searches today」二手汇总 |
| 5 · 开发者 / 系列追更 | 用户有追更表就逐个查新作动态；没有就从本轮候选的开发商反查历史爆款与续作——过去产过爆款，新作起量有保底 |
| 6 · 经典爆款二创 | 对已知爆款搜「`<游戏名>` alternative / similar / like」，筛高热度平替新作；发现某老玩法还没有像样新作，本身就是选题；语言本地化空位（只有英文站的小众玩法）一并记下 |
| 7 · 预告游戏 | 搜近期游戏展新品汇总、Steam 愿望单榜新闻；预告期反应强烈的记入候选池分散下注（不重仓单一押注——开发解散 / 发布不及预期两种风险） |
| 9 · AI 类游戏 | 搜 `AI dungeon alternatives`、`AI text adventure games` 一类词——词新、站少、传统渠道覆盖不到 |

**B 组 · 用户通道（登录墙 / 付费墙，agent 拿不到就明说，不装）**

| 渠道 | 怎么协作 |
|---|---|
| 2b · TikTok / YouTube 低粉异常 | 用户刷到可疑的把链接贴进来，agent 做验证与记录；不假装自己刷过 TikTok |
| 8 · 付费数据工具 | 用户有账号：agent 给出精确查询式（词 / 市场 / 指标），用户回填数字后再进入打分 |

产出物：候选列表——游戏名 + 来源渠道 + 原始信号（带链接）+ 抓取日期。

## Step 2 — 逐候选两分钟快验（每个候选必做，不过此步不得入表）

1. **SERP 构成**：搜「游戏名」和「`游戏名 + guide / wiki / codes`」——前十是什么站？有论坛帖 / PDF / 低权重新站 = 弱位，新站有空位。
2. **意图满足度**：前十答的是玩家搜这个词的真实目的，还是只是字面匹配？整页答错题 = 强可做信号（方法详见 `docs/sourcing.md` 第二节）。
3. **搜索萌芽**：相关搜索 / autocomplete 里有没有 `play <名>`、`<名> unblocked` 一类长尾。
4. **可玩供给**：有没有稳定可打开的可玩页面。

## Step 3 — 判决打分（照抄 sourcing.md 第四节口径，不自创）

- **搜索需求轨** 7 项逐项摆证据打分：精确词月搜量（5/10/15/20）· KD（15/12/8/3）· SERP 弱位（10）· 趋势方向（10）· 意图匹配（10）· 可玩供给（10）· 独立需求交叉（5）。70+ 倾向【做】（再跑 game-selection 四层漏斗终审），50-69 补齐缺失证据再判，50 以下留【考虑】。
- **新游无搜量 → 早期爆发轨**：24h 内独立发布者 ≥3、传播跨 ≥2 类平台、非官方互动达标且在涨、搜索萌芽出现、有可玩页面——传播信号齐 + 搜索萌芽才升级优先调研；只有平台推荐位的留在观察。
- **KD 分档动作表**：20-39 是新站主战场；40-49 仅当弱位 + 页面能明显更好 + 接受外链成本时继续；≥50 留作副页 / 观察词。KD 40 是深查触发线，不是自动放弃线；两个工具 KD 相差 10 分以上以人工看 SERP 为准。
- 每个候选的结论必须能说出「哪几项证据齐了所以这么判」，并**点名未测项**。

## Step 4 — 落盘决策管理表

写入 `seo-reports/game-pipeline.md`（不存在则创建，存在则按游戏名更新 / 追加行，不动用户手填的结论）：

```markdown
| 游戏名 | 来源渠道 | 关键信号 | 快验结论 | 打分（未测标出） | 建议 | 决定 | 上线日期 | 网站链接 | 下次复查日 |
|---|---|---|---|---|---|---|---|---|---|
```

- 「建议」三值：**做 / 不做 / 考虑**，当天必须给一个，不许空着；【考虑】必须带复查日（首记后第 **3 / 7 / 14 / 28** 天），到期行排最前。
- 「决定 / 上线日期 / 网站链接」三列对齐 `docs/sourcing.md` 的多站运营台账口径，用户可直接搬去飞书 / Google Sheets。
- 报告尾部固定三行小结：本轮新增 N 个 / 复查到期 M 个（逐个给结论）/ 未测项清单。

下次用户说「复查关键词」「再跑一轮挖词」时：先读到期的复查行逐个重验，再挖新候选——候选池不堵死。

## Step 5 — 交接

- 建议【做】→ 跑 `docs/game-selection.md` 四层漏斗终审 → `requirements/` 两张表备素材 → `/anvil-new-article` 产页
- 词表成批就绪 → `/anvil-batch-articles`
- 站上线后 → `/anvil-refresh` 保鲜巡检、anvilwiki-ops 看数据

## 经典错误（前置）

1. 把 TikTok 播放量当需求——平台内热度不等于有人搜（红线 3）。
2. 把「查不到搜量」写成「无需求」——未测 ≠ 零（红线 2）。
3. SteamDB 抓不到就空手而归——换 steamcharts / Trends RSS / 二手汇总，通道永远不止一条。
4. 一轮填 50 个候选——一轮 3-5 个，每个都过完 Step 2 快验才算数。
5. 【考虑】行没有下次复查日——候选池从此堵死（复查节奏是排期，不是坟墓）。
