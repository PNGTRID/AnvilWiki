## 内容站为什么选 Cloudflare Pages？

对一个内容生意(而不是兴趣页面)重要的三个理由:

- **免费档无限带宽**——内容站的生死线是流量激增要不要花钱。在 Pages 上不用:免费档无限请求,前面还有全球 CDN。
- **Git 连接构建**——每次 push 到 main 自动重建重部署;没有服务器要打补丁,没有会忘的发版清单。
- **没有运行时可攻击**——静态站没有能被利用的服务端代码;安全面只剩你的域名和你的密钥。

要理解的一个取舍:Pages 服务的是**静态文件**,任何需要数据库或运行时用户生成内容的功能,需要换平台。对内容站——重读轻写——静态是正确的默认,不是妥协。

## 部署前需要什么？

三样:一个 **GitHub 账号**(fork 或创建站点仓库)、本地装好 **Node.js 和 pnpm**(只有终端路径需要——浏览器路径完全不用)、一个 Cloudflare 账号。三者免费档全部够用;任何一家都不问信用卡。

## 两条部署路径怎么选？

**浏览器路径——零终端。** Fork 模板仓库,打开仓库的 GitHub Actions 标签页,跑初始化工作流:它问与 CLI 相同的问题(站名、主题色、栏目、站点类型),把个性化后的站以 Pull Request 提交回你的 fork。合并,然后把 fork 接到 Cloudflare Pages——从此每次推送内容编辑都会自动部署上线。

**终端路径——完全控制。** Clone fork,本地跑初始化 CLI(交互式问同一套问题,带 --dry-run 模式预览每个将触碰的文件),push,让 Pages 构建。这条路径迭代更快,也是[开发工作流](/zh/landing/docs/)默认的日常内容工作方式。

两条路径落到同一个地方:一个 `*.pages.dev` 域名在服务你的站,接下来按[收录玩法](/zh/landing/tutorials/get-indexed-by-google/)让新域名进入爬取队列。

## 首次部署后应该马上配置什么？

- **站点身份**:初始化 CLI 已经重写了站点配置,但在上线的首页上确认标题和描述渲染正确——这是给搜索引擎和人看的第一眼。
- **自定义域名**(可选,一个设置):在 Pages 项目里 attach——Pages 自动配 TLS 证书;部署文档里有「先绑域名、再改站点 URL」的顺序铁律,能省一次重建。
- **环境变量**:所有你开启的可选功能——统计、广告、评论。模板把每个可选集成保持关闭直到它的 key 出现在部署环境里;部署文档有完整变量表。

## 首次部署一般什么会炸？

站点本身不会——失败模式是配置:站点 URL 没带 `https://` 前缀、构建命令指错输出目录、或 Node 版本低于站点工具链声明的地板。三者都会以响亮的构建日志错误出现,修复方法就写在报错信息里。[AI 一天建站](/zh/landing/tutorials/ai-one-day-content-site/)把整条部署流嵌在真实构建里走了一遍,从头到尾。
