答えを先に:もうサイトを「書く」のではなく「設定」します。オープンソースの静的サイトテンプレートから始め、AI アシスタントに初期設定を案内してもらい、デモのブランド情報を自分のものに置き換え、リポジトリを無料の静的ホストに接続する。このループは 1 日の集中作業で、空のフォルダから公開 URL まで到達します。あなたが書くコードはゼロです。

## 始める前に何を揃えるべき？

まず 4 つを揃えます。これが揃っていると構築は滑らかに進みます。

1. **検証済みのテーマ。** [テーマの選び方のチュートリアル](/ja/guides/pick-your-niche-tutorial/) は「作る」という決断で終わります。その決断がこのレッスンの入力です。
2. **サイトの基本情報をまとめたメモ。** 仮タイトル、扱うトピック、執筆言語。
3. **アカウント。** Git ホスティングと、後で使う静的ホスティング。どちらも無料枠があります。
4. **手元のツール。** コードエディタと AI コーディングアシスタント。足りないものはアシスタントに聞けば、コマンドと説明が返ってきます。

<Callout type="warn" title="ローカルプレビューを飛ばさない">このチュートリアルのすべては、公開前に自分のマシンでサイトが動く姿を見られることを前提にしています。ローカルでプレビューできないステップがあったら、その場でアシスタントにプレビュー方法を聞いてください。この習慣ひとつで、ほぼすべての構築トラブルが安いうちに捕捉されます。</Callout>

## AI 時代のサイト構築に必要なツールは？

構成は 4 つの役割です。各役割に無料の選択肢があるので、1 つずつ決めて先へ進みます。

| 役割 | 担うこと | 選ぶもの |
| --- | --- | --- |
| サイトテンプレート | サイト本体。ページ・レイアウト・SEO・検索 | 自分のコンテンツ型に合うオープンソースの静的サイトテンプレート |
| エディタ + AI アシスタント | ファイル編集と質問 | AI アシスタント内蔵または接続されたコードエディタ |
| リポジトリ | サイトのファイルと履歴を保存 | どの無料 Git ホストでも |
| 静的ホスティング | ビルド済みサイトを訪問者に提供 | リポジトリからの push でビルドする無料静的ホスト |

**静的** サイトを選ぶ理由。ある程度のアクセスでもホスティングが無料、ページが速く、維持すべきサーバーがありません。コンテンツサイトにとってこれが全部です。

## AI との構築ループはどう回す？

どのテンプレートを選んでも、ループは同じ 5 手です。

1. **テンプレートを手に入れる。** テンプレートの 2〜3 個のセットアップコマンドに従います。分からないコマンドは、実行前にアシスタントに貼って意味を聞く。
2. **ローカルで動かす。** 1 コマンドでプレビューが起動します。何も変える前にデモサイトが見えることを確認。
3. **設定の質問に答える。** 良いテンプレートには初期化コマンドか短い設定ファイルがあります。メモの自分のサイト情報で答えます。1 問ずつ、読んでから答える。
4. **ブランドを替える。** サイト名・タグライン・配色・ナビゲーションラベル・言語はすべてコードではなく設定ファイルにあります。アシスタントに 1 項目ずつ変えてもらい、差分を見せる。
5. **本番用にビルドする。** 1 コマンドで最終成果物が出ます。ビルドが失敗したら、エラーをアシスタントと一緒に読みます。大抵はコンテンツファイルの打ち間違いで、メッセージがファイル名を教えてくれます。

<Callout type="tip" title="AI にタスクを割り振らせる">アシスタントとの最も強い協力の仕方は「ウェブサイトの作り方を教えて」と聞くことではなく、テンプレート自身のセットアップガイドを貼って「初期化を最後まで進行して。値が必要になるたびに私に聞いて」と指示することです。アシスタントが運転し、あなたが答えを供給し、見ていないことは何も起きません。</Callout>

## サイトはどうやって無料で公開する？

デプロイは繰り返す作業ではなく、1 回の接続です。

1. **リポジトリを push** して Git ホストに置く。
2. **リポジトリを接続する。** 静的ホストの管理画面で、上のステップ 5 のビルドコマンドを向ける。
3. **ビルドを待つ。** ホストがサイトをビルドし、無料サブドメインで提供します。
4. **以後、公開は push だけ。** 新しいコンテンツを push するたびにホストが自動で再ビルドします。公開の日にやることはありません。

独自ドメインを後で買ったら、ホストの管理画面で接続すると同時に **テンプレート側のサイトアドレス設定も同じ日に変えます。** ページが間違ったアドレスを宣伝しているサイトは、検索エンジンとシェアカードの両方を混乱させます。

## 人を招待する前に何を確認すべき？

この 5 項目チェックリストを、ローカルではなく **公開された URL** で回します。

- ビルドがエラーなしで完了し、トップページが本番 URL で開く。
- ナビゲーションの全ページが開く。死んだリンクがない。
- スマートフォンで読める。
- 検索ボックスが自分の書いたコンテンツを見つけられる。
- 各記事に、自分が背負える公開日または検証日が表示されている。
